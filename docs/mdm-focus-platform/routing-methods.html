Where the call gets decided

A friend dials the student's existing number — say (925) 555-0123. Four methods could put your Do-Not-Disturb between that caller and the phone. They differ in exactly one thing: where your code sits in the path. Solid arrows are calls; dashed arrows are texts.

call path text (SMS) path allowed through held for later escapes your control

Today — no product

Baseline

1 · Port the number to your provider

Chosen
  • Everything works: caller hears your message, calls and texts truly held, whitelist rings through, identical on iPhone and Android.
  • Caller never sees a new number — they dial 925 forever. The shadow number is invisible plumbing.
  • One-time friction per student: the port (LOA + carrier PIN, 5–15 business days) and a replacement line on the family's existing plan.

2 · Carrier call forwarding (**21*…#)

Rejected — texts escape, manual toggle
  • Texts escape: SMS travels a separate network path that cannot be forwarded — the "hold texts" half of the product is impossible here.
  • Un-automatable on iPhone: no API exists to toggle forwarding; the student would dial codes manually each session — the opposite of enforced DND.

3 · App on the phone only

Rejected — partial on Android, nothing on iPhone
  • Android partial: real SMS holding and an auto-text to callers — but the caller never hears a spoken message, the call can't be parked, and RCS/iMessage bypass the hold.
  • iPhone: zero. This is the wall that forces a server into the path for any iPhone product.

4 · Become the carrier (MVNO)

Deferred — heavyweight, same result as porting

Verdict: only a server in the number's path delivers the full experience, and porting is the only practical way to put it there. Method 1 is what focus-gateway implements today — your Twilio test number stands in for a ported 925 number, and production onboarding is “port the student's number + add a hidden replacement line.” Method 4 is the same control at carrier scale, worth revisiting only if port-onboarding friction limits growth.
